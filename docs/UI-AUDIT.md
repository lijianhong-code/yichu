# 页面与组件审计

| 页面 | 主要能力 | 组件基础 |
| --- | --- | --- |
| 我的衣橱 | 单品/搭配浏览、搜索、分类筛选、上传、详情编辑、删除 | `PageHeader`、`ToggleGroup`、`Input`、`Sheet`、`AlertDialog`、`EmptyState` |

## 仍需补齐的产品能力

### P0：上线前必须处理

- 微信登录态、用户 ID 与服务端鉴权；当前状态仍主要依赖浏览器本地存储。
- 数据库持久化衣物、搭配、穿着记录和偏好；需要迁移 `localStorage` 数据。
- 衣物上传的裁剪/去背景、失败重试和人工确认；当前已接入参考图视觉识别并将低置信度单品标记为“待确认”，但生产环境仍应增加对象存储和图片处理服务。
- 天气服务缓存、城市选择和权限失败后的手动城市设置。
- 每用户限流、每日 token 预算、AI 费用监控和请求审计。

### P1：提升日常使用效率

- “今天穿”后增加舒适度、正式度和喜欢/不喜欢反馈，并用于下一次排序。
- 方案收藏、重命名、删除和按日期回放；日历补记应支持修改和撤销。
- 结果缓存：相同日期、天气和需求在短时间内不重复调用模型。
- 把 SSE 和普通 JSON 两种传输模式都提供给小程序端，以适应不同基础库和网关。

### P2：增强智能化

- 将衣物颜色、材质、厚薄和风格标签向量化，用结构化过滤 + 向量召回替代全量候选。
- 根据穿着新鲜度、历史反馈和衣物状态调整推荐排序。
- 将参考图分析拆成“观察结果”和“用户确认”两步，降低视觉模型误识别对衣橱数据的污染。

## 组件规范

- 触控控件：默认 `44px`，紧凑筛选 `40px`，大按钮 `48px`；图标按钮同样保持最小 40px。
- 卡片、弹层和输入控件使用 `rounded-lg`（8px）；Chip 使用 `rounded-full`。
- 页面顶部统一使用 `PageHeader`，底部统一使用 `BottomTabNav`，页面内容底部预留导航安全区。
- 可交互筛选使用 `ToggleGroup`，状态展示使用 `Badge`，错误使用 `Alert`，确认性危险操作使用 `AlertDialog`，空数据使用 `EmptyState`。
- 领域组件（衣物图、穿搭画布、日历格）可以保留自定义实现，但内部按钮、Tooltip、滚动区域和反馈状态必须使用 shadcn 基础组件。
- 字体统一使用系统字体栈：-apple-system、SF Pro Text、Segoe UI、PingFang SC、Noto Sans CJK SC、Microsoft YaHei；不加载远程字体。
- 正文、按钮、表单和导航不使用负字距；统计数字使用 tabular-nums。
